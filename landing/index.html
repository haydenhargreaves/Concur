The core problem

One device sees only part of the world.

Smart devices are everywhere, but each one has a narrow view: a limited field, a single kind of sensing, one point of failure.

01 · Limited sensing

A narrow view

One device covers one angle and one modality. Whatever it can't see, it can't judge.

02 · Fragile reliability

One view, one failure

Noise, occlusion or a fault silently corrupts the answer, and nothing else can check it.

03 · Costly communication

Sharing is expensive

Streaming raw data between devices burns bandwidth, adds delay and exposes private data.

The challenge: gain the reliability of many views without paying for them in communication.

Our answer

Decide at the edge. Agree in the cloud.

Each node classifies locally on its own Arduino UNO Q and publishes a tiny, standard packet. A fusion layer compares them and produces one verdict you can act on.

System architecture

Small packets. Big picture.

Node A · Vision

It watches. It understands.

  • Person detection runs on the board itself: a pre-trained model finds people in every camera frame.
  • Motion classifier tracks the person over a 1.5s window — apparent speed, scale change and direction.
  • Approaching or moving away, inferred from bounding-box growth, not guesswork.
  • Camera fault check flags a missing device and lights the LED blue.

Node B · Physical sensing

It feels. It measures.

  • Distance sensor — ranges up to 1,2 m.
  • Movement sensor — any shock beyond 0.05 g flags an abnormal disturbance at 0.95 confidence.
  • Light sensor — low-light context nudges presence confidence up.
  • Sensor-health guards — a disconnected sensor can never fake a disturbance.

One shared language

The contract

One packet. Any node.

A deliberately tiny JSON schema. The fusion layer only needs state and confidence — so adding a third node is a configuration change, not a rewrite.

// sensors/node_a/state
{
  "version":    1,
  "node":       "node_a",
  "state":      1,   // 0 idle · 1 presence · 2 abnormal
  "direction":  0,   // 0 approaching · 1 away 
  "confidence": 0.92,
  "timestamp":  1732000000,
  "health":     "HEALTHY"
}
What fought back

The hard parts, and how we fixed them.

Camera classes

Camera detector

Telling approaching from moving away took many rounds of walking at the camera. We landed on a 1.5 s window and a 3%/s change in box size.

Modulino sensors

Movement & Light sensor

At first they missed changes in light and motion. Physical tests found the right numbers: under 50 lux, a 0.05 motion change, 40 mm/s for direction.

Silence

Dead or just quiet?

A node with nothing to report looked broken. Now both nodes check in every 500 ms, even when idle. Five seconds of silence marks a node offline.

The vision

Anywhere devices must agree.

Concur is a small version of a bigger idea: cheap devices combining small messages into one decision you can trust.

01 · Safety

Care and safety

Spot a fall for someone living alone, or a person entering a machine zone, even when one sensor is blocked or fails.

02 · Security

Fewer false alarms

Confirm a real intrusion with two independent senses before anyone gets called.

03 · Spaces

Smart buildings

Know which rooms are occupied and how people flow, shared as tiny numbers, not video.
